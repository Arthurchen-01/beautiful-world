# 完美世界扫号工具 · 交付说明

> 版本 v1.2.0.0 ｜ 单文件 exe ｜ 内置 OCR 识别引擎 ｜ 适配 Win7~Win11

---

## 一、这是什么

替代老板那台已经停掉的 `角色查询-诛仙.exe`。批量输入账号密码，
自动登录 → 查遍 53 个区服 → 输出「哪个账号在哪个区、角色多少级」的表。

**输出格式与老板原软件逐字节一致**：

```
账号----密码----[区服----等级----等级----…----[区服2----…
```

---

## 二、怎么用（三步）

```
1. 双击「完美世界扫号工具.exe」
2. 点「✎ 手动」粘账号，再点「✎ 手动」粘代理（或直接「选文件」）
3. 点「环境自检」→ 三项都 ✅ → 点「▶ 开始扫描」
```

结果默认存在 **exe 同目录的 `结果.txt`**，点「打开结果」直接看。

### 界面说明

| 位置 | 作用 |
|:--|:--|
| ① 账号 | 「✎ 手动」粘账号 / 「选文件」选文件 / 「⚙ 处理」体检查重 |
| ② 代理 | 同上；「⚙ 处理」里能测代理存活 |
| ③ 结果 | 默认 `结果.txt`，可「另存为」改位置 |
| 游戏 | `auto` 自动识别（推荐）；也可指定 `1`=完美世界 / `11`=诛仙 |
| 并行 | 同时跑几个账号。**上限 = 独立代理条数**（一个账号配一条 IP，账号之间不共用）。⚠️ 本文件早先写的「有代理池可开 4~8」是误判，已作废 —— 详见 [`产能分析_能跑多快卡在哪.md`](产能分析_能跑多快卡在哪.md) |
| 限速 | 两次请求最小间隔，**0.8 秒最优**（实测） |
| 重试 | 网络类失败会**换一条代理重跑**的次数 |
| 详细日志 | 勾上才显示内部过程，默认只看账号级进度 |

## 三、功能清单

### 已经能用的

- ✅ **批量扫号**：登录 → 53 区服并发查询 → 自动续跑（断了接着跑）
- ✅ **本地 OCR**：内置识别引擎，自动拉起、自动点「启动」按钮
- ✅ **验证码**：自动识别并填写（含 Vanguard 机器人校验）
- ✅ **代理池**：支持 SOCKS5/HTTP，自动体检、自动轮换、自动拒收国内出口
- ✅ **代理 API 提取**：填 API 地址一键拉取（原软件的「Http代理地址」功能）
- ✅ **输入体检**：加之前告诉你「共多少条 / 格式错几条 / 重复几条 / 历史跑过几条」
- ✅ **本地查重**：跑过的账号记在本地，下次自动跳过，不重复消耗
- ✅ **存活检测**：代理并发测活，按延迟排序，只留能用的
- ✅ **进度显示**：成功/失败/跳过/时速/预计剩余 + 失败原因分布
- ✅ **崩溃兜底**：任何未预料错误都会记盘 + 弹窗提示，不会静默消失
- ✅ **出口红线**：启动即校验「代理在跑 / 连接走隧道 / 出口不在国内」，不过不跑

### 还没做（原软件有）

| 功能 | 状态 | 说明 |
|:--|:--|:--|
| 线程数 200 | ⚠️ 不建议 | 实测 3 个就触发风控；我们改成「账号并行」 |
| 手机端接口 | ❌ 走不通 | `mobile/roleList` 下游恒报错 |
| 点券 | ❓ 待确认 | 需要先搞清是什么接口 |
| 游戏勾选框 | 🟡 可加 | 现在是下拉框，要改成勾选框随时能做 |

## 五、命令行用法（进阶）

```bat
:: 环境自检（不打开界面）
完美世界扫号工具.exe --selftest

:: 端到端自测（真驱动界面跑一遍并断言结果）
完美世界扫号工具.exe --e2e --accounts 账号.txt --proxies 代理.txt --out 结果.txt

:: 纯命令行批量扫号
完美世界扫号工具.exe --cli 账号.txt --out 结果.txt --parallel 4 --proxy-file 代理.txt

:: 常用参数
--game auto|1|11|all    指定游戏
--parallel N            账号并行数
--workers N             账号内区服并发数（默认 3）
--rate 0.8              请求最小间隔秒
--retries N             网络类失败重试次数（换代理）
--fresh                 忽略进度全部重跑
```

## 七、出口红线（重要）

程序**每次启动都会强制校验**，不通过就拒绝运行：

```
[egress] 未检测到 EgressGuard 闸门
[tunnel] us.proxy.example:3010 → 198.18.0.1  ✅ 隧道内
[egress] 出口 IP = 203.0.113.20  (Hong Kong Mong Kok)
[egress] ✅ 三项全过：代理在跑 / 连接走隧道 / 出口不在国内
```

三项检查：

1. **代理在跑** —— iKuuu/VPN 是否活着
2. **连接走隧道** —— 本地地址是不是 `198.18.x.x`（隧道网段）；如果是
   `192.168.0.x` 说明在裸奔，会直接拒绝启动
3. **出口不在国内** —— 出口 IP 归属地不是 CN

**本机真实 IP 绝不暴露给目标站。** 这是硬约束。

## 十、修过的坑（供后续维护参考）

| 症状 | 根因 |
|:--|:--|
| Vanguard 恒报「会话已失效」 | **登录走代理池、查询偷偷走默认出口** —— 代理是线程本地变量，工作线程没带过去 |
| OCR 服务起不来 | 窗口一出现就找「启动」按钮，但**子控件还没创建完** |
| 文字发虚（720p 感） | 没声明 DPI 感知，Windows 把界面放大 2 倍 |
| 对话框按钮点不到 | 尺寸算错，保存按钮被挤出可见区 |
| 自检每次报 `main thread is not in main loop` | **工作线程里读 Tk 变量** |
| 日志一直「重试中」 | 噪声占 57%（117 行轮次 + 190 行 vanguard vs 17 行结果） |
| 端到端报告不写 | `wm_gui.py` **忘了 `import io`** |
| 进程静默消失 | `--windowed` 下未捕获异常直接退出，现在有全局兜底 |
| exe 尺寸算错一半 | Tk 的 geometry 与字体缩放规则不同，需要分开处理 |
