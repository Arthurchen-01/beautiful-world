## 二、⭐ 最可能的原因：缺 virtio 驱动

这台是 KVM 架构的云主机（香港 cognetcloud）。**这类机器的磁盘和网卡用的是 virtio 虚拟设备**，
而微软原版 Windows 安装镜像**不带 virtio 驱动**。

典型后果正好就是现在这样：

| 现象 | 对应原因 |
| :--- | :--- |
| 装完起不来 / 掉进恢复环境 | 缺 **virtio 存储驱动** → 系统找不到自己的系统盘 |
| WinRE 里网络也完全不通 | 缺 **virtio 网卡驱动** → 网卡根本没起来 |

**如果是这个原因，你自己在 WinRE 里修不好** —— 需要在安装镜像里注入 virtio 驱动，
或者让服务商用**带 virtio 驱动的模板**重装。

> 这不是你弄坏的，也不是我们软件的问题。**这是服务商装机流程的问题。**

## 四、想自己看一眼：在恢复界面点「命令提示符」

**只收集信息，先别改任何东西。** 一条一条敲，每条回车：

```bat
diskpart
```

进了 diskpart 之后再敲：

```bat
list disk
list volume
exit
```

**★ 这一步最关键**：

| `list disk` 的结果 | 说明 |
| :--- | :--- |
| **一个磁盘都没有** | 🎯 **确诊：缺 virtio 存储驱动** → 只能让服务商重装 |
| 能看到磁盘，但 `list volume` 里没有 C 盘 | 分区/盘符乱了 → 可以修 |
| 磁盘和 C 盘都在 | 是引导问题 → 可以修 |

然后继续敲：

```bat
dir C:\Windows\System32\ntoskrnl.exe
```

- 报「找不到文件」→ **系统压根没装完**，或盘符不是 C
- 列出来了 → 系统文件在，是引导坏了

```bat
bcdedit /enum
```

看输出里有没有 `Windows Boot Loader` 那一段。

**把这三段输出拍给我**（`list disk` / `list volume` 的结果、`dir` 的结果、`bcdedit` 的结果），
我就能告诉你到底是哪种，以及下一步敲什么。

## 五、⚠️ 先别敲这些

```bat
bootrec /fixmbr          ← 别敲
bootrec /fixboot         ← 别敲
bootrec /rebuildbcd      ← 别敲
```

**原因**：这台机器可能有多个磁盘。`bootrec` 系列会把引导**写到它认为"对"的那个盘上** ——
写错了会让情况更麻烦（比如把引导写到数据盘，或者覆盖掉还好的引导记录）。

**等我看完第四步的输出再定。** 大多数情况下这几条也不是必需的。

## 七-bis、★ 服务器上最容易踩的坑：Session 0 没有桌面

### 问题

这套 OCR 引擎（`图像识别POST服务.exe`）是**图形界面程序**：
它得先把窗口建出来，我们再往窗口上的「启动」按钮发消息，它才开始监听 506。

而**计划任务如果用 `SYSTEM` 或「不管用户是否登录」跑，就在 Session 0** —— 那里**没有交互桌面**。

> 窗口消息（`PostMessage` / `SetWindowPos`）本身在 Session 0 是能用的，
> 但「GUI 程序能不能在 Session 0 把窗口建起来」**我没法在这边验证**，只能到服务器上实测。

### 已经做的两手准备

**① 部署脚本会明确报出来**

`deploy_server.ps1` 第 2 步会打印当前会话和身份：

```
当前会话  : Session 0   身份 NT AUTHORITY\SYSTEM
[警告] 正在 Session 0 / SYSTEM 下运行（计划任务通常就是这样）
```

第 6 步的冒烟测试会**实际把 OCR 拉起来**，过了就是真过了。

**② 加了一个配套任务自动兜底**

部署脚本会额外注册一个 **`WMRoleScan-OCR`** 任务，在**用户登录时**（有桌面的会话里）跑：

```bat
完美世界扫号工具.exe --ocr-start
```

它把 OCR 服务常驻起来。之后 Session 0 里的主任务一连 506 就发现**已经在监听**，
`ocr_service.start()` 直接返回 —— **根本不碰窗口，坑就绕过去了**。

> 代价：需要有人登录过一次。没人登录它就只是不跑，不影响主任务。
> 想手工先拉一次：`完美世界扫号工具.exe --ocr-start`

### 如果冒烟测试真报 OCR 起不来

按部署脚本打印的提示走，三条路：

| 方案 | 做法 | 代价 |
| :--- | :--- | :--- |
| **1（最省事）** | 远程桌面登进去，手工跑一次 `完美世界扫号工具.exe --ocr-start` 让它常驻 | 重启后要重登一次 |
| **2** | 把主任务改成「只在用户登录时运行」，并保持一个远程桌面会话开着 | 得一直挂着会话 |
| **3** | 找我，把 OCR 引擎换成不依赖窗口的启动方式 | 要改代码 + 重新打包 |
