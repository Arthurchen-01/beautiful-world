## 三、迁移过程中踩到并已解决的坑

这三个坑**每一个都会让迁移失败**，而且现象都有误导性：

### 坑 1：Windows Defender 把易语言程序当病毒杀 ★★★

```
威胁名称: Adware:Win32/Flystudio      ← Flystudio = 易语言的代号
隔离日志: _MEI...\识别端\HPSocket4C.dll
          _MEI...\识别端\OCR.dll
```

Defender 在 PyInstaller 解包那一刻就删掉了网络库和 54MB 的 OCR 模型。

**误导性极强**：OCR 窗口能建出来、按钮能找到、`BM_CLICK` 返回 True，
但**一点「启动」进程就崩**（内存 9MB，只加载 7 个系统 DLL）。
**和「缺 vcomp140.dll」的现象一模一样。**

**判据**：看崩溃前**加载了几个模块**。只加载 7 个系统 DLL = 依赖文件被删；
加载了几十个 = 引擎初始化失败。

**解法**：加 Defender 排除项（部署脚本 2b 段自动做）。

> ⚠️ 客户若有**火绒 / 360 / 卡巴**，也要在那边加白名单。

### 坑 2：32 位 VC++ 运行库缺失

新装的 Windows Server 默认不带 x86 运行库，而 `XYLib.dll` 是 32 位的。

**解法**：`vc_redist.x86.exe`（服务器有外网，一条命令搞定）。

### 坑 3：出口红线只认「本机形态」

```python
if not proxy_listening():      # 要求本机 127.0.0.1:7890 有代理
    raise EgressUnsafe("拒绝开工")
tb = check_tunnel_binding()    # 要求连接绑在 198.18.x.x 隧道网段
if not tb["ok"]:
    raise EgressUnsafe("拒绝开工")
```

这是给「昆明本机 + iKuuu TUN」写的。服务器上两条都不成立 → **必然拒绝开工**。

**解法**：加「服务器形态」判定（判据完全不同，见下）。

### 附带修掉的：`netguard` 覆盖代理

`netguard` 会把调用方传的代理**覆盖**成默认的 `http://127.0.0.1:7890`，
而服务器上没有 7890 → 出口体检失败，异常又被静默吞掉 →
表现成「取不到出口 IP，代理可能在抖」。**这个特别难查。**

**解法**：用之前先 `netguard.allow_proxy()` 登记，并且不再吞异常。

## 四、迁移到一台新服务器要做什么

**已全部脚本化，约 30 分钟。** 步骤：

### 前置：新机器要求

| 项 | 要求 |
| :--- | :--- |
| 系统 | Windows Server 2019 / 2022（**桌面体验版**，不要 Server Core，不要定制版） |
| 配置 | ≥ 4 核 / ≥ 8 GB / ≥ 30 GB 可用（实测那台是 16 核 / 32 GB / 90 GB） |
| 网络 | 能直连代理商（**境外机器更好 —— 不需要第一跳**） |
| 端口 | 至少开 **3389（远程桌面）** 或 **5985（WinRM）** |

### 步骤

```powershell
# 1) 连上去（本机有 TUN 时用中转绕过）
python tools\local_relay.py --target <新IP> --map 13389:3389 --map 15985:5985
$cred = New-Object System.Management.Automation.PSCredential("administrator", (ConvertTo-SecureString "<密码>" -AsPlainText -Force))
$so = New-PSSessionOption -SkipCACheck -SkipCNCheck -SkipRevocationCheck
$s = New-PSSession -ConnectionURI "http://127.0.0.1:15985/wsman" -Credential $cred -Authentication Negotiate -SessionOption $so

# 2) 装 32 位 VC++ 运行库
Invoke-Command -Session $s -ScriptBlock {
  Invoke-WebRequest "https://aka.ms/vs/17/release/vc_redist.x86.exe" -OutFile "$env:TEMP\vcredist.exe" -UseBasicParsing
  Start-Process "$env:TEMP\vcredist.exe" -ArgumentList "/install","/quiet","/norestart" -Wait
}

# 3) 传文件（★ 单路，实测 0.78 MB/s；并行反而更慢）
Copy-Item 完美世界扫号工具.exe  -Destination "C:\WMRoleScan\wmscan.exe" -ToSession $s
Copy-Item 账号.txt             -Destination "C:\WMRoleScan\账号.txt"   -ToSession $s
Copy-Item 代理.txt             -Destination "C:\WMRoleScan\代理.txt"   -ToSession $s
Copy-Item tools\deploy_server.ps1 -Destination "C:\WMRoleScan\deploy_server.ps1" -ToSession $s

# 4) 跑部署脚本（含 Defender 排除 + 计划任务）
Invoke-Command -Session $s -ScriptBlock {
  & "C:\WMRoleScan\deploy_server.ps1" `
      -Exe "C:\WMRoleScan\wmscan.exe" -Accounts "C:\WMRoleScan\账号.txt" `
      -Proxies "C:\WMRoleScan\代理.txt" -WorkDir "C:\WMRoleScan" -IntervalMinutes 30
}
```

### ⚠️ 三个必须记住的操作细节

1. **`.cmd` 里别用中文文件名** —— 用 `[System.Text.Encoding]::ASCII` 写 `.cmd` 会把
   中文变成 `????????`，报「系统找不到指定的路径」。**用 ASCII 的 exe 名最省事。**
2. **别在 WinRM 会话里 `Start-Process`** —— 会话一关子进程就被带走。
   **要用计划任务跑。**
3. **传大文件用单路** —— `Copy-Item -ToSession` 单路 0.78 MB/s（84MB 用 107 秒）；
   实测 4 路并行**反而更慢且易失败**。

## 五、硬约束：产能达不到客户要的量级

**这是唯一一条「不可行」的，必须说清楚。**

```
工具实际吞吐（服务器上）：
  · 错密码号（登录就被拒）    --parallel 32 → 1,129 账号/小时
  · 真号（要扫满 53 区服）    --parallel 6  →    41 账号/小时
客户要的                      10,000 账号/分钟 = 600,000 账号/小时
差距                          约 530 倍（按真号）/ 约 530 倍（按错密码号）
```

**★ 产能高度取决于「账号成色」**，同一个工具两种号差 27 倍：

| 账号类型 | 单账号耗时 | 说明 |
| :--- | ---: | :--- |
| 错密码号 | ~18 s | 登录失败就结束，~5 个请求 |
| **真号** | **~523 s** | 要扫满 53 个区服 + 重试，~53+ 个请求 |

按老板原软件的成色（93% 错密码 + 7% 真号）算：

```
平均每账号耗时 = 0.93 × 18 + 0.07 × 523 ≈ 53 秒
--parallel 32 的吞吐 ≈ 32 / 53 ≈ 0.60 账号/秒 ≈ 2,160 账号/小时
→ 离 600,000/小时 还差 278 倍
```

**瓶颈在代理商（arxlabs），不在服务器，也不在工具：**

```
直连目标站（不经代理）:  280 ms 一次完整往返     ← 目标站很快
经 arxlabs:             4,700 ~ 10,900 ms       ← 慢 15~20 倍
```

**而且并行 16 → 32 吞吐几乎不涨（0.296 → 0.314）—— 已经饱和。**

**代码层面没什么可榨的了**（连接复用本来就有；详见
[`吞吐实测报告.md`](吞吐实测报告.md) 第六节，我一开始那个「复用能提速 4.6 倍」
的判断是错的）。

**要提产能只有三条路**：

| 路子 | 预期收益 | 代价 |
| :--- | :--- | :--- |
| 换低延迟代理商 | 2~5 倍 | 换供应商 |
| 加代理容量 | 线性（要 500 倍就要 500 倍连接） | 要花钱买几万条 |
| **减少每账号请求数** | **可能几十倍** | **得客户确认「要不要扫满 53 区服」** |

> **★ 最后一条才是真正的杠杆。** 如果客户要的其实是「筛出有效账号」
> （不关心具体在哪个区、多少级），那每账号只要 ~5 个请求，
> 产能直接上一个数量级。
>
> **这个必须问清楚 —— 它比任何技术优化都重要。**
