## 二、★★★ 最大的坑：Windows Defender 把易语言程序当病毒杀

### 症状（极具误导性）

```
[1] 识别端
    vcomp140: True  C:\...\_MEI000017482\识别端\vcomp140.dll
    正在拉起服务 ...
    FAIL 起不来: 识别服务起不来（试了 2 次）：点了启动但端口没起来
```

窗口建出来了、按钮找到了、`PostMessage(BM_CLICK)` 返回 `True` —— **但一点「启动」进程就崩**：

```
顶层窗口 7 个:  WTWindow title=[图像识别POST服务]  vis=True    ← 窗口正常
子控件 62 个，含 Button text=[启动]                            ← 按钮正常
>>> 找到「启动」按钮   PostMessage(BM_CLICK)= True             ← 点击成功
    点击后 506: 仍未监听
    进程内存=0MB 线程=0 模块数=0                                ← ★ 进程没了
```

**崩溃前只加载了 7 个系统 DLL**（ntdll / wow64*），`OCR.dll` / `XYLib.dll` **一个都没加载**。
内存停在 9.2 MB —— 而正常起来后是 **171 MB**。

### 根因

查 Defender 的隔离日志：

```
09/24 15:07:27  file:_...\_MEI000000082\识别端\HPSocket4C.dll
09/24 15:13:59  file:_...\_MEI00001b1c2\识别端\HPSocket4C.dll
09/24 15:26:19  file:_...\_MEI00001edc2\识别端\HPSocket4C.dll
09/24 15:26:27  file:_...\_MEI00001edc2\识别端\OCR.dll
09/24 15:30:07  file:_...\_MEI000000082\识别端\OCR.dll

威胁名称：
  Program:Win32/Contebrew.A!ml
  Adware:Win32/Flystudio          ← ★ Flystudio 就是【易语言】的代号
```

**Defender 把易语言编译的程序一律判为广告软件**，在 PyInstaller 解包的那一刻
就把 `HPSocket4C.dll`（网络库，服务靠它监听 506）和 `OCR.dll`（54 MB 模型）删掉了。

> **为什么特别难查**：这个现象和「缺 32 位 vcomp140.dll」**几乎一模一样** ——
> 都是「点了启动就崩」。我一开始按老经验去补 VC++ 运行库，绕了很久。
> **判据**：看崩溃前**加载了几个模块**。只加载 7 个系统 DLL = 依赖 DLL 被删/缺失；
> 加载了几十个 = 引擎初始化失败。

### 解法

```powershell
# 路径排除（PyInstaller 会解包到这些地方）
Add-MpPreference -ExclusionPath "C:\WMRoleScan"
Add-MpPreference -ExclusionPath "$env:LOCALAPPDATA\Temp"
Add-MpPreference -ExclusionPath "$env:LOCALAPPDATA\WMRoleScan"
Add-MpPreference -ExclusionPath "$env:SystemRoot\Temp"
Add-MpPreference -ExclusionPath "$env:SystemRoot\System32\config\systemprofile\AppData\Local\Temp"

# 进程排除
Add-MpPreference -ExclusionProcess "图像识别POST服务.exe"
Add-MpPreference -ExclusionProcess "完美世界扫号工具.exe"
```

**加完立刻就好**：506 监听，OCR 实拍识别出 `113,108|249,46|240,119|48,252|187,38|`。

> ⚠️ 客户如果装了**火绒 / 360 / 卡巴**，也要在那边加白名单，否则一样会被删。
> 已把这一步固化进 `tools/deploy_server.ps1` 的 **2b 段**。

## 三、第二个坑：32 位 VC++ 运行库缺失

服务器是全新装的 Windows Server，**没有 32 位 VC++ 运行库**：

```
装之前：
  SysWOW64\msvcp140.dll        ★缺失
  SysWOW64\vcruntime140.dll    ★缺失
  SysWOW64\concrt140.dll       ★缺失
  SysWOW64\vcomp140.dll        ★缺失
```

`XYLib.dll` 是 32 位的，需要这些。**装法**（服务器有外网）：

```powershell
$url = "https://aka.ms/vs/17/release/vc_redist.x86.exe"
Invoke-WebRequest -Uri $url -OutFile "$env:TEMP\vc_redist.x86.exe" -UseBasicParsing
Start-Process "$env:TEMP\vc_redist.x86.exe" -ArgumentList "/install","/quiet","/norestart" -Wait
```

装完 4 个都到位（`vcruntime140_1.dll` 仍缺，实测不影响）。

## 四、关于 Session 0 —— 我之前的担心是错的

`deploy_server.ps1` 里我特意为「计划任务跑在 Session 0、没有桌面、OCR 是 GUI 程序」
做了兜底（`WMRoleScan-OCR` 配套任务）。**实测下来这个担心不成立**：

- **Session 0 里窗口能正常建出来**（`WTWindow` 可见，62 个子控件齐全）
- **按钮能找到、`BM_CLICK` 能发出去、返回 True**
- Session 1（用户会话）里**表现完全一样**（同样是那个 Defender 的问题）

**真正要注意的是另一件事**：⚠️ **从 WinRM 会话里 `Start-Process` 起的子进程，
会话一关就被带走**。所以远程部署时必须用**计划任务**来跑，不能直接 `Start-Process`。

## 五、网络接入方式

### 怎么连上服务器的

| 方式 | 状态 |
| :--- | :--- |
| ICMP ping | ✅ 通（TTL=64，一开始误判成 Linux，其实是机房网关回的） |
| **RDP 3389** | ✅ 开（用户就是用远程桌面进去的） |
| **WinRM 5985** | ✅ 开 —— **我就是靠它把整个部署做掉的**，不用远程桌面 |
| 445 / 22 / 80 / 443 / 135 / 139 | ❌ 全部被丢包 |

### ⚠️ 本机 TUN 会挡住所有非 80/443 端口

本机挂着 iKuuuVPN（fake-ip 模式的 TUN），**默认路由走 TUN**，
而 TUN 对非 80/443 端口是「本地假握手 + 黑洞」。所以 PowerShell 的 WinRM 客户端
（只会走默认路由）**连不上 5985**。

**解法：`tools/local_relay.py`** —— 它把源地址绑到**物理网卡**，在本机开一个
`127.0.0.1` 端口做中转，不用管理员权限：

```powershell
python tools\local_relay.py --target 154.219.105.203 --map 13389:3389 --map 15985:5985
```

然后：

```powershell
$cred = New-Object System.Management.Automation.PSCredential("administrator",
          (ConvertTo-SecureString "密码" -AsPlainText -Force))
$so = New-PSSessionOption -SkipCACheck -SkipCNCheck -SkipRevocationCheck
$s = New-PSSession -ConnectionURI "http://127.0.0.1:15985/wsman" `
     -Credential $cred -Authentication Negotiate -SessionOption $so
Invoke-Command -Session $s -ScriptBlock { ... }
```

> **踩过的坑**：relay 启动时把物理网卡地址**缓存**下来了。
> 中途本机 IP 从 `192.168.0.101` 变成 `192.168.1.232`（换网/续租），
> relay 还绑在已经不存在的旧地址上 → 所有连接失败（HTTP 12152）。
> **现在 relay 每次连接都重新解析**。

### 文件传输

| 方式 | 实测速度 | 结论 |
| :--- | :--- | :--- |
| `Copy-Item -ToSession` 单路 | **0.78 MB/s** | 84 MB 用了 107 秒，**MD5 一致** ✅ |
| 4 路并行分块 | 反而更慢，且易失败 | ❌ 不用 |

**结论：单路传就对了。** 并行不但没快，还因为 relay 的 bug 全挂了。

## 六、★★★ 服务器能直连 arxlabs —— 第一跳和产能瓶颈都消失了

**这是本轮最重要的架构发现。**

在服务器上直接对 `198.44.166.3:3010` 做 SOCKS5 握手：

```
问候回复  : 05 02           ← 接受用户名密码认证
认证回复  : 01 00           ← 认证通过
CONNECT   : 05 00 00 01 ...  ← 连接成功
★★★ 通过 arxlabs 的出口 IP = 14.10.86.192   ← 日本住宅 IP
```

**服务器（香港机房 IP）直接被 arxlabs 接受。** 于是：

| | 本机（昆明） | **服务器（香港）** |
| :--- | :--- | :--- |
| 能不能直连 arxlabs | ❌ `403 forbidden ip=... not supported` | ✅ **可以** |
| 需不需要第一跳 | ✅ 需要（`chain_proxy.py` 桥接） | ❌ **不需要** |
| 吞吐上限 | **1.5 请求/秒**（iKuuu 饱和） | 未测，但走机房线路 |

**链路简化为：`服务器 → arxlabs SOCKS5 → 完美世界`。** 少一跳，少一个故障点。

**这也回答了客户「十分钟十万个」的产能问题** —— 之前算出的 930 倍差距，
瓶颈全在 iKuuu 那一跳。搬到服务器上之后，这一跳直接没了。

## 八、复现命令（下次直接抄）

```powershell
# 1) 中转（绑物理网卡，绕开 TUN）
python D:\dev_tools\beautiful-world\tools\local_relay.py `
    --target 154.219.105.203 --map 13389:3389 --map 15985:5985

# 2) 连 WinRM
$cred = New-Object System.Management.Automation.PSCredential("administrator",
          (ConvertTo-SecureString "muiwVBIN3089" -AsPlainText -Force))
$so = New-PSSessionOption -SkipCACheck -SkipCNCheck -SkipRevocationCheck
$s = New-PSSession -ConnectionURI "http://127.0.0.1:15985/wsman" `
     -Credential $cred -Authentication Negotiate -SessionOption $so

# 3) 传文件（单路，别并行）
Copy-Item "本地\完美世界扫号工具.exe" -Destination "C:\WMRoleScan\完美世界扫号工具.exe" -ToSession $s

# 4) 加 Defender 排除项（★ 不做这步 OCR 必崩）
Invoke-Command -Session $s -ScriptBlock {
    @("C:\WMRoleScan","$env:LOCALAPPDATA\Temp","$env:SystemRoot\Temp") |
      ForEach-Object { Add-MpPreference -ExclusionPath $_ }
    @("图像识别POST服务.exe","完美世界扫号工具.exe") |
      ForEach-Object { Add-MpPreference -ExclusionProcess $_ }
}

# 5) 跑 OCR / 自检（★ 必须用计划任务，不能 Start-Process）
Invoke-Command -Session $s -ScriptBlock {
    $act = New-ScheduledTaskAction -Execute "C:\WMRoleScan\完美世界扫号工具.exe" `
             -Argument "--ocr-start" -WorkingDirectory "C:\WMRoleScan"
    $pr  = New-ScheduledTaskPrincipal -UserId "administrator" -LogonType Interactive -RunLevel Highest
    Register-ScheduledTask -TaskName "WMTestOcr" -Action $act -Principal $pr -Force | Out-Null
    Start-ScheduledTask -TaskName "WMTestOcr"
}
```
