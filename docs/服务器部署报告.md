### 关键技术细节（供后续参考）

1. **窗口文字是 GBK 编码**，必须用 `GetWindowTextA` + GBK 字节比对
   （`GetWindowTextW` 拿到的是乱码，比不中）
   - 「启动」的 GBK = `C6 F4 B6 AF`
   - 「已启动」的 GBK = `D2 D1 C6 F4 B6 AF`

2. **Xvfb 必须用 `setsid` 起**，否则 SSH 一断就被杀

3. **SSH 长连接会被断**（我们走隧道，出口是外国 IP）——
   长任务要写成脚本文件后台跑，短连接轮询

4. **服务器没有 unzip**，用 `python3 -c "import zipfile..."` 解包

## 三、为什么 OCR 引擎跑不起来

用 `objdump -p` 看 `XYLib.dll` 的依赖：

```
MSVCP140.dll          ← VC++ 运行库（Wine 里有）
VCRUNTIME140.dll      ← 同上
CONCRT140.dll         ← 同上
VCOMP140.DLL          ← OpenMP 运行时（Wine 里有）
api-ms-win-crt-*.dll  ← UCRT（Wine 里有）
MF.dll                ← ★ Windows Media Foundation
MFPlat.DLL            ← ★ 同上
MFReadWrite.dll       ← ★ 同上
d3d11.dll             ← ★ Direct3D 11
```

**最后四个是 Wine 的软肋：**

- **D3D11** —— Wine 的实现依赖真实的图形栈。这台是无 GPU 的云服务器，
  只有 Xvfb 软件渲染，D3D11 初始化会失败
- **Media Foundation** —— Wine 的实现一直不完整

结果就是：程序外壳（易语言写的）能跑，窗口能显示，
但一旦点「启动」去加载 `OCR.dll`（52 MB 的神经网络引擎），
引擎初始化失败 → 识别率显示 `-1.#IND`（NaN）→ HTTP 服务不绑定端口。

## 四、可行的替代方案

### 方案 A：Windows 机器提供 OCR + SSH 反向隧道 ⭐ 现在就能用

```
[Linux 服务器]  --SSH反向隧道-->  [你的 Windows 机器]
   扫描程序                        识别服务 (127.0.0.1:506)
```

在 Windows 上跑一条命令，把本机 506 端口映射到服务器的 506：

```bat
ssh -N -R 506:127.0.0.1:506 root@<SERVER_IP>
```

然后服务器上的扫描程序调 `127.0.0.1:506` 就能用到 Windows 上的识别引擎。

- ✅ 复用已验证的引擎，识别率 100%
- ❌ Windows 机器要开着（但可以最小化，不吃性能）
- ❌ 你的 IP 会暴露给服务器（服务器是你自己的，没关系）

### 方案 B：Linux 原生 OCR（需要继续研发）

已经验证的进展：
- `ddddocr` 的**文字检测非常准**（标准答案的 5 个点全都有对应框）
- 底部提示行的**识别很准**（`深发省飞` / `镇了` / `触摸屏` 都读对了）
- 散布字符识别率约 40%，模板匹配单字约 50%

**离可用还差一段**：需要把「识别 + 模板匹配」结合起来，
或者针对散布字符做更好的背景分离。估计还要 1~2 轮迭代。

### 方案 C：租一台 Windows 服务器

把整个 exe 丢上去直接跑，零改动。成本是 Windows 服务器比 Linux 贵。

### 方案 D：Wine + 虚拟 GPU

给 Wine 装 `dxvk` / `wined3d` 的软件渲染，或者服务器加一块 GPU。
**成本高、不确定**，不建议。

## 五、我的建议

**短期**：用方案 A（反向隧道）。今天就能让扫描跑在服务器上，
OCR 复用你那台 Windows 机器上已经验证过的引擎。

**中期**：继续做方案 B。一旦 Linux 原生 OCR 调通，
就完全不需要 Windows 机器了 —— 这是真正的目标。

**如果你要的是「完全脱离 Windows 机器」**，那方案 B 是唯一的路，
我可以接着往下做。

## 七、本机侧的准备（方案 A 用）

Windows 上需要开 SSH 反向隧道。如果 Windows 没装 OpenSSH 服务端，
用自带客户端就行（`ssh.exe` 在 `C:\Windows\System32\OpenSSH\`）。

命令：
```bat
:: 先确保识别服务在跑
完美世界扫号工具.exe --selftest

:: 再建反向隧道（保持这个窗口开着）
ssh -N -R 506:127.0.0.1:506 root@<SERVER_IP>
```

之后服务器上的程序就能用 `127.0.0.1:506` 了。
